# 反馈回路

[English](feedback-loop.md) · **简体中文**

一张图只是一半的活，另一半是你读它时的想法。mind-atlas 让你直接在图上说出来，再交给智能体，中间不需要任何服务。

```text
页面（你的浏览器）                               智能体（你的会话）
──────────────────                               ─────────────────
写反馈、引用节点
  │ 存在 localStorage
  ▼
「复制给 AI」 ── 一段文字 ────────────────────▶  读这段文字，逐条处理
                                                   │
                                                   ├─ 要求改图就先改 outline-*.md
                                                   └─ reply.py <工作目录> <编号> "回复" --orig "..."
                                                        │ 追加进 replies.json，运行 build.py
刷新页面  ◀── 带着回复重新生成的页面 ──────────────────┘
```

## 你要做的

1. 在右栏**写**。可以引用一个节点（鼠标移到它上面点橙色的 💬，或点详情里的「引用这一条去反馈」），或引用一句话（在详情或大纲视图里选中，
   点「引用这段」），也可以完全不引用。
2. **交**：点「交」，或按 ⌘/Ctrl + 回车。它会出现在反馈列表里，标着「还没复制给 AI，只存在这个浏览器里」。
3. 点**「复制给 AI」**，所有还没复制过的反馈会整理成一段文字放进剪贴板，这些条目随即标为「已复制给 AI」。
   「全部再复制一次」会把所有条目再发一遍。
4. 把这段文字**粘贴**到和智能体的会话里。
5. 智能体回复之后，**刷新页面**，每条回复就显示在它回答的那条反馈下面。

一条反馈可以「改」（拿回输入框重新编辑；如果之前已经复制出去过，再交的时候会注明是改写了之前那条），也可以「删」（只从你的浏览器里删掉）。

## 智能体收到的那段文字

```text
【导图反馈】小区旧书漂流角全貌（示例），2 条
页面文件：/home/you/mindmaps/book-corner/book-corner.html
回复写回页面：python3 "/home/you/.claude/skills/mind-atlas/scripts/reply.py" "/home/you/mindmaps/book-corner" <编号> "回复"

1. [F1016-123456-ab] 10月16日 12:34
   引用：问题与下一步 › 一、先保书 › 梅雨季书会发霉（整条）
   说：到底有多潮？先放一个湿度计观察一个月，再决定要不要花钱买除湿盒。

2. [F1016-123458-cd] 10月16日 12:35
   引用：目的与规矩 › 目的：让邻居之间的旧书流动起来，不让书压在家里
         「不求借阅登记，只求书架上常有新书。」
   说：现在每个月大概有多少人拿书？
```

- 第一行在中文页面上以 `【导图反馈】` 开头，英文页面上以 `[Mind map feedback]` 开头。
- 方括号里的编号（`F` + 月日 + 时间 + 两位随机字符）就是智能体传给 `reply.py` 的那个编号。
- 引用会显示节点的标题路径（不含根节点），引用了一句话时还会带上这句话。没有引用、但写的时候选中了某个节点的，
  会注明选中的是哪个节点。
- 用 `--no-paths` 生成的页面没有「页面文件」和「回复写回页面」这两行，智能体没有命令可跑；只在要分享的页面上这样用。在这样的页面上回复反馈时，`reply.py` 也要加 `--no-paths`，否则重新生成时路径又会被写回页面。

## 智能体怎么处理

对每一条：

1. 弄懂它；如果是在问某个事实，就回到来源去核对。
2. 如果你要求改图，就改对应的 `outline-*.md`（加节点、改状态、纠正事实）并运行 `build.py`。改节点标题会让别人对它的旧引用失效，
   所以非必要不改标题。
3. 记录回复：

   ```bash
   python3 <skill_dir>/scripts/reply.py <工作目录> F1016-123456-ab "已在这条风险下加了一个节点……" --orig "到底有多潮？……"
   ```

   这会追加进 `replies.json` 并重新生成页面。`--orig` 带着你的原话：如果你换了浏览器（你自己写的反馈不在这个浏览器里），
   页面仍能把你的问题和回复放在一起显示。同一个编号可以回复多次，回复按时间排列。
4. 在会话里告诉你它做了什么。
5. 如果这次交流定下了某个决定，记到项目里放决定的地方，并把图上对应的【建议】改成【已定】或【待做】。

## 东西存在哪

| 什么 | 存在哪 | 说明 |
|---|---|---|
| 你的反馈条目 | 浏览器的 `localStorage`，键 `mm:<id>:items` | `<id>` 是 `meta.json` 里的 `id`（没写就是 `title`）。从不上传 |
| 没交的草稿、右栏宽度、是否收起 | `localStorage`，键 `mm:<id>:draft`、`:w`、`:fold` | |
| 智能体的回复 | `<工作目录>/replies.json` | 一个 JSON 列表，每项 `{"id", "ts", "text", "orig"}`；生成页面时嵌进页面 |

因为反馈是按浏览器、按 `id` 存的：

- 用另一个浏览器打开同一个文件，能看到回复（给了 `--orig` 就连同你的原话），但看不到你自己的条目。
- 改了 `id`（没写 `id` 时是改了 `title`），页面就把你写过的东西全忘了。`id` 定一次就别再改。
- 浏览器在你从磁盘打开的所有文件之间共用本地存储，两张图的 `id` 相同，反馈就会串到一起。每张图用自己的 `id`。
- 清除本地文件的网站数据会删掉你的条目。清理之前先复制给智能体。

## 为什么这样设计

没有要忘记关的服务，没有要认证的东西，放在 U 盘里也能用。代价是多一步手动操作（把那段文字粘贴到会话里）。
对于一个人一口气读完、成批回复的图来说，这是个划算的交换。见 [README](../README.zh-CN.md#为什么是静态页不起服务) 里的「为什么是静态页，不起服务」。
