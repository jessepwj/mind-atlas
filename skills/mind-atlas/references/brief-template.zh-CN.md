# 派单模板（分支调研）

给子智能体派「梳理某个分支」的活时用。提炼自一次全景梳理的 7 份真实派单（每份 40 行左右）。把 `{{ }}` 里的占位换成这件事的内容，其余规矩原样保留。

## 派之前先想清楚

- **必须写明模型。** 调研类默认用能听懂清楚派单的最便宜的模型（Claude Code 里用 Agent 工具并写 `model: haiku`；其他 agent 用各自的子智能体机制）。合并、验收、判断类不派最便宜的。
- **材料清单要具体**：写到文件路径、目录、要 grep 的关键词。让子智能体自己去找「该看什么」，它会漏，也会读到过时的文档。
- **建议一级分支要给**：它不知道你想要的结构。给 6～12 个建议分支，其中最后两个固定是「已知问题、坑和经验」「还没做完的事、可以优化的地方」。
- **一份派单一个分支，互不重叠。** 切法见 [等级与子智能体](levels.zh-CN.md)。
- **多个一起派**：在同一条消息里发出所有派单，让它们并行。派出后主会话马上去写主干，不干等。
- 要写的状态标签见 [大纲写法](outline-format.zh-CN.md)，派单里只列这件事会用到的几个。

## 模板

下面整段放进子智能体的 prompt。

````
你在帮「{{项目名}}」做一次全貌梳理，负责其中一个分支：**{{分支名}}**（{{这个分支是什么，一两句话，让它知道范围}}）。今天是 {{日期}}。主会话会把各分支汇总成一张多级思维导图给 {{读者}} 看，用来{{目的，比如后面优化和结构化 / 据此做某个决定 / 讲清楚给别人听}}。

## 规矩（必须遵守）
- 只读：不改任何文件（除了下面要你写的那一份输出文件），不跑有副作用的命令（{{按这件事列出禁止的动作，比如：不重启或加载或卸载任何服务、不发消息、不做写入类的网络请求、不跑会改数据的脚本、不提交代码}}）。可以用 cat、sed、grep、ls、find 看文件，{{这件事允许的只读命令，比如读日志尾部、看配置、对本机服务做只读 GET}}。
- 不抄任何口令、token、密钥、cookie 的值；只说「在哪个文件、什么权限」。{{如果材料里有私人内容，加一句：不抄聊天、对话、档案的正文，只说结构和数量级。}}
- 全部用中文写。每个节点写成短的完整句或名词短语，**不许用省略号截断**（中文的省略号和连着的三个英文点都不行），不许只报条数不说是什么。
- 关键事实（路径、时刻、数量、状态、负责人）要回源文件核对过再写，并在节点后用括号注明来源文件路径。
- 材料里有互相矛盾或明显过时的地方，两种说法都写，并注明哪个更新、依据是什么；不要自己挑一个当成事实。

## 要看的材料（先看这些，需要再顺着找）
- {{材料 1：路径 + 看什么，比如「要读完」「只看开头说明和主函数」「只看结构和少量样例，不整份读大文件」}}
- {{材料 2}}
- {{材料 3}}

## 要产出的内容
写到文件 `{{输出文件绝对路径，比如 <工作目录>/A-<分支名>.md}}`，用 Markdown 嵌套列表（每级两个空格缩进），可以 {{层数，比如 4～5}} 级，越完整越好。建议一级分支：
1. {{建议分支 1}}
2. {{建议分支 2}}
3. {{建议分支 3}}
{{再按这个分支的实际情况列若干条；最后两条固定如下}}
{{N-1}}. 已知问题、坑和经验（从文档、日志、代码注释里找）
{{N}}. 还没做完的事、可以优化的地方（只写有依据的，注明出处）
状态用标签：{{这件事会用到的几个，比如 【在用】【已停】【进行中】【待做】【问题】}}。

## 交付前自检
写完后自己回头核对，查到没问题、自己满意了再交，不要写完就报：{{这件事最容易错的几类，比如：每个定时的时刻、每个路径是不是真的存在、有没有省略号截断、有没有漏掉目录里明显属于这个分支的文件}}。最后回复里给：输出文件路径、你核对了哪些事实（列 5～10 条，每条带证据，比如命令和输出摘要）、你拿不准的地方。回复正文不用重复整份内容。
````

模板里所有 `{{ }}` 都是写给填模板的人的说明，派出去之前要全部换成这件事的具体内容，不要原样发给子智能体。

## 填写说明

| 占位 | 怎么填 |
|---|---|
| 禁止的动作 | 想一遍这件事里有哪些「看一眼就会改变状态」的操作：重启服务、加载定时任务、发消息、提交表单、跑采集脚本。逐个写出来，比写一句「不要有副作用」有用得多。 |
| 材料清单 | 主会话自己先浏览一遍目录，写具体路径。重要文档标「要读完」，大文件标「只看开头说明」。 |
| 建议一级分支 | 基本是「它是什么 / 怎么运转 / 数据落哪 / 定时和通路 / 已知问题 / 没做完的」这一类问题的变体。 |
| 自检项 | 取这个分支里最容易写错的事实类型（时刻、路径、状态），让它自己核对。 |

## 派出之后

1. 并行期间，主会话写主干大纲和横向分支。
2. 报告回来后先看它「拿不准」的部分，再按 [等级与子智能体](levels.zh-CN.md) 里的抽查清单回源核对。
3. 把报告改写成 `outline-<编号>.md`：报告的括号来源改成 `〔〕`，状态用最新进展核正，重复的合并，过长的拆开（写法见 [大纲写法](outline-format.zh-CN.md)）。报告本身留在工作目录里当原料，不直接拼进页面。
4. 子智能体违反规矩的（比如读了不该读的内容、把密钥打印出来、改了不该改的文件），立刻记下来，在回复用户时一句话说明，不要藏。
